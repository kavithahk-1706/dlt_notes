21. What are autoencoders, and how do they relate to principal component analysis (PCA) in terms of dimensionality reduction?

An autoencoder is a feedforward network trained to reproduce its own input: the encoder maps \(x_i\) to a hidden representation \(h\), and the decoder reconstructs \(\hat x_i\) from \(h\). Training uses ordinary backpropagation to make \(\hat x_i\) close to \(x_i\).

\[h=g(Wx_i+b),\qquad \hat x_i=f(W^{*}h+c)\]

Choice of decoder \(f\) and loss

InputsDecoder \(f\)Loss
Binary, \(x_{ij}\in\{0,1\}\)Logistic (outputs in (0,1))\(L=-\sum_{j=1}^{n}\bigl[x_{ij}\log\hat x_{ij}+(1-x_{ij})\log(1-\hat x_{ij})\bigr]\)
Real-valued, \(x_{ij}\in\mathbb{R}\)Linear: \(\hat x_i=W^{*}h+c\)\(\min\ \frac{1}{m}\sum_{i=1}^{m}\sum_{j=1}^{n}(\hat x_{ij}-x_{ij})^2\)

Undercomplete vs overcomplete

  • Undercomplete (\(\dim(h)<\dim(x_i)\)): if \(x_i\) can still be reconstructed well, \(h\) is a loss-free compressed encoding that captures the important characteristics of \(x_i\) — the same goal as PCA.
  • Overcomplete (\(\dim(h)\ge\dim(x_i)\)): the network can simply copy \(x_i\) into \(h\) and out again (identity mapping), learning nothing useful. It needs regularisation (Q22, Q24, Q25).

Relation to PCA

The encoder of an autoencoder is PCA when (i) encoder and decoder are linear, (ii) the loss is squared error, and (iii) the inputs are mean-centred and scaled, \(X=\tfrac{1}{\sqrt m}X'\), so that \(X^{T}X\) is the covariance matrix. Proof sketch, ignoring biases:

\[\min_{H,W^{*}}\ \|X-HW^{*}\|_F^{2}\ \xrightarrow{\ \text{SVD}\ }\ HW^{*}=U_{:,\le k}\Sigma_{k,k}V_{:,\le k}^{T}\ \Rightarrow\ H=U_{:,\le k}\Sigma_{k,k}=XV_{:,\le k},\quad W^{*}=V_{:,\le k}^{T}\]

Hence the encoder weights are \(W=V_{:,\le k}\). \(V\) holds the eigenvectors of \(X^{T}X\), which is the covariance matrix, so \(W=P\), the PCA projection matrix.

PCAAutoencoder
MappingLinear onlyLinear, or non-linear with sigmoid / tanh units
How foundEigen-decomposition / SVD (closed form)Gradient descent with backpropagation
StrengthSimple, unique orthonormal basisLearns curved (non-linear) structure PCA cannot capture

Worked example — size of an autoencoder

For a 28×28 image, \(x\in\mathbb R^{784}\). Use a hidden layer of 32 units, so \(\dim(h)=32<784\) (undercomplete, a 24.5× compression):

ParametersShapeCount
Encoder \(W,\ b\)\(32\times784,\ 32\)25 088 + 32
Decoder \(W^{*},\ c\)\(784\times32,\ 784\)25 088 + 784

The 32 numbers in \(h\) must contain enough information to rebuild all 784 pixels, which forces the network to keep only the most important structure of the data.

What autoencoders are used for

  • Dimensionality reduction / feature learning: use \(h\) as a compact input for another model.
  • Pre-training of deep networks layer by layer (Q31).
  • Denoising and anomaly detection: a point unlike the training data has a large reconstruction error \(\|x-\hat x\|^2\).

22. How do sparse autoencoders differ from traditional autoencoders, and what are some applications of sparse autoencoders in deep learning?

The core difference

  • A traditional (vanilla) autoencoder places no constraint on how many hidden neurons are allowed to fire for a given input. If the autoencoder is overcomplete (hidden dimension \(\geq\) input dimension), it has enough capacity to simply copy its input straight through to the output — learning the trivial identity function rather than anything meaningful about the data.
  • A sparse autoencoder differs by adding an explicit constraint that forces most hidden neurons to remain inactive for most inputs, so that only a small subset of neurons may fire for any given input. This constraint is what prevents the trivial identity solution, and it is enforced through the mechanism below.

For a hidden neuron with sigmoid activation, "active" means its output is near 1, and "inactive" means near 0.

The average activation of hidden neuron \(l\) across the dataset is:

\[ \hat{\rho}_l = \frac{1}{m}\sum_{i} h(x_i)_l \]

A small sparsity target \(\rho\) is chosen (e.g. \(\rho = 0.005\)), and a penalty is added that pushes \(\hat{\rho}_l\) toward \(\rho\) for every hidden neuron \(l\):

\[ \Omega(\theta) = \sum_l \left[ \rho\log\frac{\rho}{\hat{\rho}_l} + (1-\rho)\log\frac{1-\rho}{1-\hat{\rho}_l} \right] \]

This is a KL-divergence-style term between two Bernoulli distributions (one with mean \(\rho\), one with mean \(\hat{\rho}_l\)) — it is minimized exactly when \(\hat{\rho}_l = \rho\), i.e. when the neuron's actual average activation matches the sparsity target. The total loss being minimized is:

\[ \hat{L}(\theta) = L(\theta) + \Omega(\theta) \]

where \(L(\theta)\) is the ordinary reconstruction loss. The network is now optimizing two competing objectives at once: reconstruct the input well (\(L\)), while keeping most neurons inactive (\(\Omega\)). This tension is the mechanism that produces the difference stated above — it is what prevents the trivial identity solution that an unconstrained, overcomplete traditional autoencoder is free to learn.

Summary of the difference

Traditional AESparse AE
No constraint on how many hidden neurons are allowed to fireExplicit penalty \(\Omega(\theta)\) forcing most neurons to stay near-inactive
An overcomplete AE can trivially copy the input through to the outputSparsity prevents this — the network must reconstruct using only a few active neurons, forcing it to learn genuinely useful, disentangled features
Learned filters, when visualized, often look unstructured or noisyLearned filters tend to be more interpretable — e.g. localized, pen-stroke-like or edge-like detectors

Applications

  • Unsupervised pretraining: The sparse autoencoder is trained on unlabeled data to learn a compact representation. The resulting encoder weights are then used to initialize the first layer of a supervised classifier, in place of random initialization, so the network begins training from already-meaningful features. This reduces the amount of labeled data required to reach good performance.
  • Anomaly detection: When trained exclusively on normal data, the network learns to reconstruct normal patterns accurately using its learned sparse codes. An anomalous input cannot be represented well by these codes and therefore produces a higher reconstruction error, which is used directly as an anomaly score, without requiring labeled anomalous examples.
  • Interpretable feature extraction: Each hidden neuron's weight vector, reshaped into the dimensions of the input, forms a filter representing the pattern that maximally activates that neuron. Since sparsity restricts only a few neurons to be active per input, each active neuron corresponds to a distinct, localized pattern (e.g. an edge or stroke) rather than an entangled combination of features, making the representation easier to interpret.
  • Compression: Since most hidden neurons remain inactive for a given input, only the indices and values of the active neurons need to be stored, analogous to sparse matrix storage. This gives a more compact representation than a dense code of equal dimensionality.
  • Feature learning / transfer learning: Representations learned by a sparse autoencoder on one task can be reused as input features for a different, related task, avoiding the need to learn a new representation from scratch.
  • Robustness to noise: Since only a small subset of neurons is active per input, minor input noise is less likely to alter which neurons fire, giving the representation some robustness to noise even without the explicit input corruption used in denoising autoencoders (Q24).
  • Stacked sparse autoencoders: Multiple sparse autoencoders can be trained greedily, one layer at a time, with each layer's hidden representation serving as the input to the next. The resulting stack of encoders is combined and fine-tuned end-to-end as a classifier — a standard method for training deep networks before more effective initialization and optimization techniques became available.

Note: The observation that sparse coding of natural images produces filters resembling the edge-detecting simple cells of the primary visual cortex (Olshausen & Field, 1996) is not itself an application. It is a theoretical justification supporting sparsity as a principled constraint, rather than an arbitrary one.

Source: CS7015 Lecture 7 (Khapra), Module 7.5.

23. How does bias-variance trade-off can be managed using regularization techniques such as L2 regularization?

Bias–variance trade-off

For an unseen point, with \(\hat f\) the learned model and \(f\) the true function,

\[E\bigl[(y-\hat f(x))^2\bigr]=\underbrace{\bigl(E[\hat f(x)]-f(x)\bigr)^2}_{\text{Bias}^2}+\underbrace{E\bigl[(\hat f(x)-E[\hat f(x)])^2\bigr]}_{\text{Variance}}+\sigma^2\]

A simple model has high bias and low variance (underfits). A complex model has low bias but high variance (overfits): training error keeps falling while test error rises. We want the sweet spot in between, so regularisation is used to restrain complexity: \(\ \min_\theta\ \tilde L(\theta)=L_{\text{train}}(\theta)+\Omega(\theta)\).

L2 regularisation (weight decay)

\[\tilde L(w)=L(w)+\frac{\alpha}{2}\|w\|^{2},\qquad \nabla\tilde L(w)=\nabla L(w)+\alpha w\]
\[w_{t+1}=w_t-\eta\bigl(\nabla L(w_t)+\alpha w_t\bigr)=(1-\eta\alpha)\,w_t-\eta\,\nabla L(w_t)\]

Every update first shrinks the weights by the factor \((1-\eta\alpha)\) (hence "weight decay") and then takes the usual gradient step.

Why it reduces variance

Expand \(L\) around its optimum \(w^{*}\) with Hessian \(H=Q\Lambda Q^{T}\). The regularised minimum is

\[\tilde w=Q(\Lambda+\alpha I)^{-1}\Lambda\,Q^{T}w^{*},\qquad \text{component } i \text{ is scaled by } \frac{\lambda_i}{\lambda_i+\alpha}\]
  • \(\lambda_i\gg\alpha\): factor \(\approx1\) — directions that matter for the loss are kept.
  • \(\lambda_i\ll\alpha\): factor \(\approx0\) — unimportant directions are shrunk to zero.
  • Effective number of parameters \(=\sum_i\frac{\lambda_i}{\lambda_i+\alpha}<n\), so the model behaves as a simpler one.
Strength of \(\alpha\)Effect
Large \(\alpha\)Strong shrinkage: lower variance, higher bias (risk of underfitting)
Small \(\alpha\)Close to the unregularised model: higher variance, lower bias
\(\alpha\) chosen on validation errorLands near the sweet spot

Other ways of managing the same trade-off: early stopping (Q29), dataset augmentation (Q26), dropout, parameter sharing and tying. For autoencoders the same penalty is written \(\lambda\|\theta\|^{2}\) (Lecture 7).

Worked example — the shrinkage factor

Let the Hessian eigenvalues be \(\lambda=\{9,\,1,\,0.1\}\) and \(\alpha=1\). The factor \(\lambda_i/(\lambda_i+\alpha)\) for each direction is

\(\lambda_i\)FactorMeaning
9\(9/10=0.90\)important direction: almost unchanged
1\(1/2=0.50\)halved
0.1\(0.1/1.1\approx0.09\)unimportant direction: almost removed

Effective number of parameters \(=0.90+0.50+0.09\approx1.49\), against 3 actual parameters.

24. What is the role of denoising autoencoders in deep learning, and how do they enhance the robustness of a model?

Core idea: a denoising autoencoder (DAE) deliberately corrupts its input using a stochastic process \(P(\tilde{x}_{ij}\mid x_{ij})\) before feeding it into the encoder — but the training objective still asks the network to reconstruct the original, uncorrupted input, not the corrupted one it actually received.

Corruption process

\[ P(\tilde{x}_{ij}=0 \mid x_{ij}) = q \qquad \text{(flipped to 0 with probability } q\text{)} \] \[ P(\tilde{x}_{ij}=x_{ij} \mid x_{ij}) = 1-q \qquad \text{(retained as-is otherwise)} \]

(An alternative corruption process is additive Gaussian noise: \(\tilde{x}_{ij} = x_{ij} + \mathcal{N}(0,1)\).)

Why this works — the key mechanism

The training objective is:

\[ \min \sum_{i,j} (\hat{x}_{ij} - x_{ij})^2 \]

Notice this compares the reconstruction \(\hat{x}\) against the original \(x\), not the corrupted \(\tilde{x}\) that was actually fed in. This one design choice is what makes denoising autoencoders work: it is no longer useful for the model to simply copy the corrupted input \(\tilde{x}_i\) through to \(h\) and back out to \(\hat{x}_i\), because that copy would reproduce the corrupted version — and the loss explicitly penalizes that mismatch. The only way to reduce the loss is for the model to infer the missing/corrupted values from their correlations with the other, uncorrupted elements of \(x_i\). In other words, it is forced to learn the true underlying structure of the data, rather than memorizing an identity mapping.

Evidence of robustness (from visualization)

  • A vanilla (non-denoising) autoencoder's hidden neurons, when visualized as the input pattern that maximally activates each one, do not learn many meaningful patterns.
  • A denoising autoencoder's hidden neurons behave like pen-stroke detectors — for example, a neuron may fire specifically for a stroke shape found in digits like '0', '2', '3', '8', '9'.
  • As the corruption level \(q\) increases (e.g. from 25% to 50%), the learned filters become wider — the neuron must draw on more surrounding pixels to remain confident about a stroke, since any single pixel's information is now less reliable.
  • On other datasets, DAE hidden neurons behave like edge detectors — a capability plain PCA cannot produce, since PCA is restricted to linear, global directions of variance.

Role in deep learning

  • Learns more robust, generalizable representations than a vanilla autoencoder, since the network cannot rely on trivially copying its input.
  • Useful as an unsupervised pretraining step — for example, on MNIST digit recognition, a DAE can first learn a compact representation \(h \in \mathbb{R}^d\), and a classifier is then trained on \(h\) instead of on the raw 784-dimensional pixel input.
  • Improves resilience to noisy or corrupted real-world inputs at inference time, since the model was explicitly trained to "see through" corruption during training.
Source: CS7015 Lecture 7 (Khapra), Module 7.4.

25. Explain the concept of contractive autoencoders and how they differ from traditional autoencoders.

A contractive autoencoder (CAE) is an overcomplete autoencoder regularised so that it cannot learn the identity function. It does this by penalising how sensitive the hidden representation is to small changes in the input.

Objective

\[\hat L(\theta)=L(\theta)+\Omega(\theta),\qquad \Omega(\theta)=\|J_x(h)\|_F^{2}=\sum_{j=1}^{n}\sum_{l=1}^{k}\Bigl(\frac{\partial h_l}{\partial x_j}\Bigr)^{2}\]

\(L(\theta)\) is the usual reconstruction loss (squared error or cross-entropy). \(J_x(h)\) is the \(k\times n\) Jacobian of the encoder; its \((l,j)\) entry says how much hidden unit \(l\) changes for a small change in input \(j\). For a sigmoid encoder \(h_l=\sigma(W_l x+b_l)\) it has the closed form \(\partial h_l/\partial x_j=h_l(1-h_l)W_{lj}\).

Intuition

  • \(L(\theta)\) wants \(h\) to capture variations in \(x\), otherwise \(x\) cannot be reconstructed. \(\Omega(\theta)\) wants \(h\) to ignore variations (\(\partial h_l/\partial x_j\to0\)).
  • The two terms pull against each other, so \(h\) stays sensitive only to the strongest variations seen in the training data (direction \(u_1\)) and becomes insensitive to unimportant, noise-like directions (\(u_2\)). This is a PCA-like behaviour: keep high-variance directions, suppress low-variance ones.

Difference from traditional autoencoders

Worked example — the penalty for one hidden unit

Take a single sigmoid hidden unit with two inputs, \(h=\sigma(w_1x_1+w_2x_2+b)\). Its Jacobian entries are \(\partial h/\partial x_j=h(1-h)w_j\), so

\[\Omega=\|J_x(h)\|_F^{2}=\bigl[h(1-h)\bigr]^{2}\,(w_1^{2}+w_2^{2})\]
Hidden value \(h\)\(h(1-h)\)\([h(1-h)]^2\)Sensitivity
0.50.250.0625highest — sigmoid is steepest here
0.950.04750.0023~28× smaller — unit is saturated

So the penalty is small if the weights are small or if the unit is saturated, in which case moving the input hardly changes \(h\). Minimising \(L+\Omega\) therefore keeps a unit sensitive only along directions that the reconstruction really needs.

Contractive versus denoising

Both make \(h\) robust to small input changes. The denoising autoencoder does it stochastically, by training on corrupted inputs; the contractive autoencoder does it analytically, by penalising the Jacobian directly (and only for infinitesimal changes).

26. Explain dataset augmentation and discuss any four commonly used augmentation techniques in deep learning.

Dataset augmentation means creating new training examples from existing ones by applying transformations that use knowledge of the task and do not change the label. If \(\mathcal{T}\) is a set of such transformations,

\[\mathcal{D}'=\mathcal{D}\ \cup\ \bigl\{\,(T(x_i),\,y_i)\ :\ (x_i,y_i)\in\mathcal{D},\ T\in\mathcal{T}\bigr\}\]

The network is then trained on \(\mathcal{D}'\), which is much larger than the original data. It is most natural for images (classification, object recognition) and speech; for other tasks it is often unclear how to generate such data.

Four commonly used techniques

TechniqueTransformationNote
Rotation\(x'=R(\varphi)\,x,\ \ R(\varphi)=\begin{bmatrix}\cos\varphi&-\sin\varphi\\ \sin\varphi&\cos\varphi\end{bmatrix}\) applied to pixel coordinatesUse small angles; large ones can change the class (6 vs 9)
Shifting (translation)\(x'(u,v)=x(u-t_u,\ v-t_v)\), shifted horizontally / verticallyMakes the model tolerant to object position
Flipping\(x'(u,v)=x(W-1-u,\ v)\)Fine for natural objects (a flipped cat is still a cat), wrong for digits and text
Blurring / noiseBlur: convolve with a Gaussian kernel. Noise: \(\tilde x=x+\varepsilon,\ \varepsilon\sim\mathcal{N}(0,\sigma^2)\)Robust to sensor noise and low resolution

Other common ones: scaling / zooming, random cropping, colour jitter. The lecture illustrates augmentation on a digit "2" (rotated by 20° and 65°, shifted vertically and horizontally, blurred, some pixels changed) — all still labelled "2".

Practical points

  • Transformations must be label-preserving and realistic for the task.
  • Applied on the fly, with fresh random parameters every epoch; only the training set is augmented, not the test set.

Worked examples

  • Rotation by 90°: \(R(90^\circ)=\begin{bmatrix}0&-1\\1&0\end{bmatrix}\), so the point \((2,1)\) goes to \((-1,2)\). For a small angle such as \(20^\circ\), \(R=\begin{bmatrix}0.94&-0.34\\0.34&0.94\end{bmatrix}\).
  • Shift by one pixel to the right: \(x'(u,v)=x(u-1,v)\), i.e. every pixel moves from column \(u-1\) to column \(u\).
  • Size of the new data set: 60 000 images × (5 rotations × 4 shifts) = 1 200 000 labelled variants, without collecting a single new image.

Choosing transformations

Ask: would a human still give the same label? A rotated, shifted or slightly blurred "2" is still a 2, so these are safe. A vertically flipped "6" looks like a "9" and a mirrored "2" is no longer a valid digit, so these are unsafe for digit recognition. The augmentation set is therefore chosen using knowledge of the task, not blindly.

27. How does dataset augmentation improve the performance of deep learning models?

Augmentation improves a model mainly by reducing overfitting (variance) and by teaching it the invariances we want.

1. More (effective) training data

Overfitting happens when a flexible model has too little data. Augmentation supplies many label-preserving variants of every example, so the training loss averages over the transformations instead of memorising single images:

\[\min_{\theta}\ \frac{1}{N}\sum_{i=1}^{N}\ \mathbb{E}_{T\sim\mathcal{T}}\ \ell\bigl(f(T(x_i);\theta),\,y_i\bigr)\]

2. Learns invariance

Seeing a digit rotated, shifted or blurred, all with the same label, forces \(f(T(x))\approx f(x)\). The model stops depending on position, small rotations or noise that do not matter for the label, so it generalises to unseen test images.

3. Acts as a regulariser

Adding noise \(\tilde x_i=x_i+\varepsilon_i,\ \varepsilon\sim\mathcal{N}(0,\sigma^2)\) to the inputs of a linear model \(\tilde y=\sum_i w_i\tilde x_i\) gives

\[E\bigl[(\tilde y-y)^2\bigr]=E\bigl[(\hat y-y)^2\bigr]+\sigma^{2}\sum_{i=1}^{n}w_i^{2}\]

which is exactly an L2 (weight-decay) penalty. So augmentation with noise is regularisation in disguise (Q23).

Effect and cautions

AspectEffect of augmentation
VarianceLower — smaller gap between training and validation error
BiasUnchanged if the transformations are realistic; can increase if they are not
RobustnessBetter on shifted, rotated, blurred or noisy inputs
CostMore computation per epoch; transformations must keep the label (do not flip digits, do not over-rotate 6/9)

Derivation — input noise equals L2 penalty

Let \(\hat y=\sum_iw_ix_i\) and the noisy output \(\tilde y=\sum_iw_i(x_i+\varepsilon_i)=\hat y+\sum_iw_i\varepsilon_i\), where the \(\varepsilon_i\) are independent with \(E[\varepsilon_i]=0\), \(\mathrm{Var}(\varepsilon_i)=\sigma^2\). Then

\[E\bigl[(\tilde y-y)^2\bigr]=E\bigl[(\hat y-y)^2\bigr]+2\,E\Bigl[(\hat y-y)\sum_iw_i\varepsilon_i\Bigr]+E\Bigl[\Bigl(\sum_iw_i\varepsilon_i\Bigr)^{2}\Bigr]\]

The middle term is 0 because \(E[\varepsilon_i]=0\) and the noise is independent of \(\hat y-y\). In the last term the cross products vanish, leaving \(\sum_iw_i^2\,E[\varepsilon_i^2]=\sigma^2\sum_iw_i^2\). This gives the L2 form shown above: noisy training is the same as minimising the original loss plus \(\sigma^2\|w\|^2\), so the noise level \(\sigma^2\) plays the role of \(\alpha\).

28. Describe the concepts of parameter sharing and tying in the context of autoencoders.

Autoencoders — Overview

An autoencoder is a feedforward neural network trained to reconstruct its input. It consists of two parts: an encoder that maps input \(\mathbf{x}\) to a hidden representation \(\mathbf{h}\), and a decoder that maps \(\mathbf{h}\) back to a reconstruction \(\hat{\mathbf{x}}\).

\[\mathbf{h} = g(W\mathbf{x} + \mathbf{b}) \quad \text{(encoder)}\] \[\hat{\mathbf{x}} = g(W^{*}\mathbf{h} + \mathbf{b}^{*}) \quad \text{(decoder)}\]

Here \(W\) is the encoder weight matrix, \(W^{*}\) is the decoder weight matrix, and \(g\) is an activation function (e.g., sigmoid). The network is trained by minimising a reconstruction loss between \(\mathbf{x}\) and \(\hat{\mathbf{x}}\).

Parameter Sharing

Parameter sharing means that the same set of parameters (weights) is used across different parts of the model. This is a form of regularisation because it reduces the total number of free parameters, thereby reducing model complexity (\(\Omega(\theta)\)).

In Convolutional Neural Networks (CNNs), parameter sharing is a core design principle — the same convolutional filter (kernel) is applied across all spatial locations of the input. This means each filter learns one feature (e.g., an edge) that is reused everywhere, drastically reducing the parameter count compared to a fully connected layer.

In Recurrent Neural Networks (RNNs), the same weight matrices \(W\), \(U\), and \(V\) are shared across all time steps. The network at each time step is executing the same function with the same parameters — only the input and hidden state change.

Parameter Tying

Parameter tying is a specific form of parameter sharing where two sets of weights are constrained to be related (typically one is the transpose of the other). In autoencoders, this means:

\[W^{*} = W^{T}\]

That is, the decoder weight matrix \(W^{*}\) is constrained to be the transpose of the encoder weight matrix \(W\). This is also called tied weights.

Effects of tying weights in autoencoders:

  • Reduces the number of learnable parameters by half (only \(W\) needs to be learned; \(W^{*}\) is derived from it).
  • Acts as a regulariser — reduces the capacity of the autoencoder, preventing it from simply learning the identity function.
  • This is especially important for overcomplete autoencoders (where \(\dim(\mathbf{h}) > \dim(\mathbf{x})\)), which can trivially copy the input to the hidden layer and back without learning useful representations.

Soft Weight Sharing

An alternative to hard tying is soft weight sharing, where instead of forcing \(W^{*} = W^{T}\), a penalty is added to the loss function to encourage the encoder and decoder weights to be similar:

\[\hat{L}(\theta) = L(\theta) + \lambda \|W - W^{*T}\|^{2}_{F}\]

Here \(\lambda\) is the regularisation parameter and \(\|\cdot\|_F\) denotes the Frobenius norm. This allows the weights to differ slightly while still being encouraged towards agreement.

29. Discuss the concept of early stopping as a regularization technique in deep learning.

As training proceeds, training error keeps falling, but beyond some point validation error starts to rise because the model begins to overfit. Early stopping stops training near the minimum of the validation error instead of running until the training error reaches 0.

Algorithm (with patience \(p\))

best_error = ∞ ;  best_model = None ;  wait = 0
for step k = 1, 2, ...:
    train for one epoch
    val_error = validation error of the current model
    if val_error < best_error:
        best_error = val_error ;  best_model = copy of model ;  wait = 0
    else:
        wait = wait + 1
        if wait == p:                  # no improvement for p steps
            stop training
return best_model                      # model from step k − p

Patience \(p\) avoids stopping on a single noisy rise. Early stopping can be combined with other regularisers such as L2.

Why it is a regulariser

Start from \(w_0=0\) and let \(H=Q\Lambda Q^{T}\) be the Hessian at the optimum \(w^{*}\). After \(t\) gradient-descent steps,

\[w_t=Q\bigl[I-(I-\eta\Lambda)^{t}\bigr]Q^{T}w^{*}\]

This equals the L2 solution \(\tilde w=Q(\Lambda+\alpha I)^{-1}\Lambda Q^{T}w^{*}\) when \((I-\eta\Lambda)^{t}=(\Lambda+\alpha I)^{-1}\alpha\). So the number of steps \(t\) plays the role of \(1/\alpha\): stopping early (small \(t\)) behaves like strong weight decay. Also \(|w_{t+1}-w_0|\le\eta t|\tau|\) (\(\tau\) bounds the gradient), so weights along unimportant, small-gradient directions cannot grow far within \(t\) steps.

AdvantagesDrawbacks
Simple, no change to the model or loss; saves training timeNeeds a held-out validation set
Works with any model; combines with L2 and dropoutStops before the training loss is fully minimised

Worked example — patience \(p=3\)

The model returned is the one saved at epoch 3, not the last one trained. If epoch 4 had gone back down below 0.35, wait would reset to 0 and training would continue.

Reading the curves

  • Training error decreases at every epoch, so it cannot tell us when to stop; only the held-out validation error can.
  • The gap between the curves is the generalisation gap — early stopping stops training before this gap becomes large.

30. Explain the concept of loss functions. Discuss the different types of loss functions used in deep learning.

What is a Loss Function?

A loss function (also called objective function, error function, or cost function) quantifies the deviation between the predicted output \(\hat{y}\) and the true output \(y\). The goal of training is to find parameters \(\theta\) that minimise this loss over the training data:

\[\theta^{*} = \arg\min_{\theta} \; \frac{1}{N} \sum_{i=1}^{N} \mathcal{L}(y_i, \hat{y}_i)\]

The choice of loss function depends on the task (regression vs. classification) and the output activation function used.

1. Squared Error Loss

Used primarily for regression tasks where \(y_i \in \mathbb{R}^n\). The output activation is typically linear (identity function).

\[\mathcal{L}(\theta) = \sum_{i=1}^{N} \| y_i - \hat{y}_i \|^{2} = \sum_{i=1}^{N} \sum_{j=1}^{n} (y_{ij} - \hat{y}_{ij})^2\]

It penalises large deviations quadratically, making it sensitive to outliers. It is convex with respect to \(\hat{y}\) and is the standard loss for function approximation.

2. Cross-Entropy Loss (Binary)

Used for binary classification where \(y_i \in \{0, 1\}\). The output activation is the sigmoid function: \(\hat{y} = \sigma(a) = \frac{1}{1 + e^{-a}}\).

\[\mathcal{L}(\theta) = -\sum_{i=1}^{N} \Big[ y_i \log(\hat{y}_i) + (1 - y_i) \log(1 - \hat{y}_i) \Big]\]

When \(\hat{y}\) is close to the correct label, the loss is low; when it is far away, the loss approaches infinity. This provides stronger gradients for misclassified examples than squared error would in classification.

3. Cross-Entropy Loss (Multi-class)

Used for multi-class classification where \(y\) is a one-hot encoded vector over \(K\) classes. The output activation is the softmax function:

\[\hat{y}_k = \text{softmax}(a_k) = \frac{e^{a_k}}{\sum_{j=1}^{K} e^{a_j}}\]

The cross-entropy loss for multi-class is:

\[\mathcal{L}(\theta) = -\sum_{i=1}^{N} \sum_{k=1}^{K} y_{ik} \log(\hat{y}_{ik})\]

Since \(y\) is one-hot, this simplifies to \(-\log(\hat{y}_c)\) where \(c\) is the true class. Minimising this is equivalent to maximising the probability assigned to the correct class.

Why Cross-Entropy over Squared Error for Classification?

When using a sigmoid output with squared error, the gradient includes a \(\sigma'(a)\) term, which becomes very small when \(\sigma(a) \approx 0\) or \(1\) (saturation). This means learning is extremely slow for highly wrong predictions. Cross-entropy avoids this problem — the \(\sigma'(a)\) term cancels out during backpropagation, yielding a gradient proportional to \((\hat{y} - y)\), which provides a strong learning signal even when the prediction is far off.
