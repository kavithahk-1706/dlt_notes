11. Explain in detail about the concept of gradient based learning.

  • Goal: find θ = [w, b] minimizing loss L(θ). Guesswork doesn't scale beyond a couple parameters — need a principled way to move through the error surface.
  • Taylor series argument: L(θ+ηu) ≈ L(θ) + η·uᵀ∇L(θ) for small η. The move is favorable only if uᵀ∇L(θ) < 0.
  • uᵀ∇L(θ) = k·cos(β) where β is angle between u and ∇L(θ); this is most negative when β = 180°, i.e. u points exactly opposite to the gradient.
  • Update rule: w_(t+1) = w_t − η∇w_t, b_(t+1) = b_t − η∇b_t — move opposite to the gradient, scaled by learning rate η.
  • Where the curve is steep, gradient is large → big updates. Where curve is gentle (flat), gradient is small → slow progress (motivates momentum-based methods, Q12).
Source: CS7015 Lecture 5 (Khapra), Modules 5.1–5.2.

12. How does Momentum Based Gradient Descent work and how is it different from other optimization algorithms?

Observation: vanilla GD is slow in regions with gentle slope because the gradient itself is small there. Intuition: if we're repeatedly asked to move in the same direction, we should gain confidence and take bigger steps — like a ball gaining momentum rolling downhill.

Update rule

update_t = γ · update_(t−1) + η∇w_t
w_(t+1) = w_t − update_t

Expanding: update_t = γ^(t−1)·η∇w₁ + γ^(t−2)·η∇w₂ + ... + η∇w_t — each past gradient contributes, decayed geometrically by γ.

Behavior

  • In gentle-slope regions, momentum carries the update along even though the current gradient is small → much faster convergence than vanilla GD.
  • Downside: when the error surface has a valley with steep walls on either side, momentum overshoots and oscillates ("u-turns") in and out of the minima valley before settling — but even with these oscillations it still converges faster overall than vanilla GD (e.g. after 100 iterations, momentum reaches error ~0.00001 vs vanilla GD still stuck at 0.36).

Comparison with other optimizers

AlgorithmKey ideaLimitation it fixes
Vanilla GDMove opposite gradient—
Momentum GDAccumulate exponentially-decayed history of gradientsSlow progress on gentle slopes
NAG (Nesterov)"Look ahead" — compute gradient at the partially-updated point w_t − γ·update_(t−1)Momentum's large oscillations/overshoot
AdaGradPer-parameter learning rate, decayed by cumulative squared gradientsSparse features not getting enough updates
RMSPropExponentially decayed accumulation instead of AdaGrad's ever-growing sumAdaGrad's learning rate decaying to zero too fast
AdamRMSProp's adaptive rate + momentum's cumulative gradient history, with bias correctionCombines benefits of both

So momentum differs from NAG in when it computes the gradient (current point vs. look-ahead point), and differs from AdaGrad/RMSProp/Adam in that it doesn't adapt the learning rate per-parameter — it only accumulates direction/velocity.

13. Write a python code for Batch Gradient Descent and Mini Batch Gradient Descent.

import numpy as np

def sigmoid(z): return 1/(1+np.exp(-z))

def compute_grad(X, y, w, b):
    y_hat = sigmoid(X.dot(w) + b)
    error = y_hat - y
    grad_w = X.T.dot(error) / len(X)
    grad_b = np.mean(error)
    return grad_w, grad_b

# ---- Batch (Vanilla) Gradient Descent: uses ALL data each step ----
def batch_gd(X, y, w, b, lr=0.1, epochs=100):
    for _ in range(epochs):
        grad_w, grad_b = compute_grad(X, y, w, b)
        w -= lr * grad_w
        b -= lr * grad_b
    return w, b

# ---- Mini-Batch Gradient Descent: uses batches of size B ----
def minibatch_gd(X, y, w, b, lr=0.1, epochs=100, batch_size=32):
    n = len(X)
    for _ in range(epochs):
        idx = np.random.permutation(n)
        X, y = X[idx], y[idx]
        for start in range(0, n, batch_size):
            end = start + batch_size
            Xb, yb = X[start:end], y[start:end]
            grad_w, grad_b = compute_grad(Xb, yb, w, b)
            w -= lr * grad_w
            b -= lr * grad_b
    return w, b

Key distinction: Batch GD makes 1 update per epoch (uses whole dataset — exact gradient, guaranteed loss decrease, but slow per update on large N). Mini-batch GD makes N/B updates per epoch (approximate but much faster and less oscillatory than pure SGD, typical B = 16/32/64).

14. How does basis transformation using principal component analysis (PCA) help in reducing the dimensionality of data in deep learning?

Wishlist: represent data using fewer dimensions such that (a) the data has high variance along the retained dimensions (informative), and (b) the new dimensions are uncorrelated / linearly independent (non-redundant).

Setup

Given zero-mean, unit-variance data X (rows = data points), transform to a new orthonormal basis P: X̂ = XP. We want the covariance of the transformed data, (1/m)X̂ᵀX̂ = PᵀΣP, to be a diagonal matrix D — this means zero covariance between new dimensions (off-diagonal = 0) and non-zero variance retained on the diagonal.

The answer: P = eigenvectors of the covariance matrix

Σ = (1/m)XᵀX   (covariance matrix)

The orthogonal matrix P that diagonalizes Σ (PᵀΣP = D) is exactly the matrix whose columns are the eigenvectors of XᵀX — this follows from Eigenvalue Decomposition. This works because eigenvectors of a symmetric matrix are automatically orthogonal and (for distinct eigenvalues) linearly independent — precisely the "convenient basis" we want.

Dimensionality reduction step

Once we have all n eigenvectors ranked by eigenvalue, we keep only the top-k eigenvectors (largest eigenvalues = highest variance directions) and discard the rest. This is proven optimal two ways:

  • Reconstruction-error view: minimizing Σ(xᵢ − x̂ᵢ)ᵀ(xᵢ − x̂ᵢ) over the discarded (n−k) dimensions is solved exactly by discarding the eigenvectors with the smallest eigenvalues.
  • Variance view: the variance captured along the i-th principal eigenvector direction equals λᵢ/m (its scaled eigenvalue) — so keeping the top-k eigenvectors by eigenvalue directly maximizes retained variance.

Practical example (eigenfaces)

For m face images, each 100×100 (10,000-dim), X ∈ ℝ^(m×10000). Instead of storing all 10,000 dimensions per image, we keep only the top ~100 eigenvectors of XᵀX ("eigenfaces") as a one-time basis, then store just k scalar coefficients αᵢ per image — dramatically reducing storage with minimal quality loss.

15. Explain the Adam optimisation algorithm in detail.

Adam (Adaptive Moment Estimation) = "do everything RMSProp does to fix AdaGrad's decay problem, plus use a cumulative history of gradients (like momentum)." It combines the adaptive per-parameter learning rate of RMSProp with the velocity/momentum idea.

Update rule

m_t = β₁·m_(t−1) + (1−β₁)·∇w_t   (first moment — mean of gradients, like momentum)
v_t = β₂·v_(t−1) + (1−β₂)·(∇w_t)²   (second moment — uncentered variance, like RMSProp)
m̂_t = m_t / (1 − β₁ᵗ)    v̂_t = v_t / (1 − β₂ᵗ)   (bias correction)
w_(t+1) = w_t − (η / (√v̂_t + ε)) · m̂_t

In practice β₁ = 0.9, β₂ = 0.999, ε = 1e−8.

Why bias correction is needed

Since m₀ = 0, early estimates of m_t are biased toward zero (m_t is a weighted sum of gradients starting from zero). Formally, E[m_t] = E[g]·(1−βᵗ), so dividing by (1−βᵗ) makes E[m̂_t] = E[g] — an unbiased estimate, especially important in the first few timesteps.

Why Adam works well

  • The momentum term (m_t) smooths the direction, reducing oscillation, similar to momentum-based GD.
  • The adaptive term (v_t) scales the effective learning rate down for parameters with consistently large gradients and up for those with small/sparse gradients — same benefit as RMSProp/AdaGrad.
  • Considered the "default choice" for most deep learning problems — robust to initial learning rate choices in practice, though some later work shows convergence issues in specific cases.

16. How do the various optimization algorithms (GD, momentum-based GD, NAG, AdaGrad, RMSProp, Adam) impact the convergence rate?

AlgorithmConvergence behavior
Vanilla GDSlowest — stalls badly on gentle slopes since updates are proportional to the (small) local gradient; navigates ravines/valleys very slowly.
Momentum GDMuch faster on gentle slopes (velocity accumulates), but oscillates/overshoots in narrow valleys — takes u-turns before settling. Still net faster than vanilla GD overall (e.g. reaches ~1e-5 error while vanilla GD is stuck at 0.36 after 100 iters).
NAGFaster and more stable than plain momentum — the "look-ahead" gradient lets it correct course sooner, so oscillations are smaller and shorter.
AdaGradGreat early on for sparse features (gives them larger effective learning rates), but the ever-growing denominator (Σ gradients²) causes the learning rate to decay to near-zero over time — can get stuck before reaching the minimum (e.g. stops moving in the "b" direction near convergence).
RMSPropFixes AdaGrad's stalling by using an exponentially-decayed running average of squared gradients instead of an ever-growing sum — sustains progress near convergence where AdaGrad got stuck.
AdamGenerally fastest / most robust in practice — combines RMSProp's adaptive per-parameter rates with momentum's cumulative gradient history; taking a cumulative history clearly speeds convergence versus RMSProp alone in the lecture's comparisons.

Overall trend: adaptive learning-rate methods (AdaGrad → RMSProp → Adam) generally converge faster than fixed-rate methods (GD, momentum, NAG) on problems with sparse or ill-conditioned gradients, because they give each parameter its own effective step size instead of one global η.

17. Write about RMSprop optimization algorithm in detail.

Motivation: AdaGrad decays the learning rate too aggressively — its denominator v_t = v_(t−1) + (∇w_t)² only ever grows, so frequently-updated parameters eventually stop learning almost entirely.

v_t = β·v_(t−1) + (1−β)·(∇w_t)²
w_(t+1) = w_t − (η/√(v_t+ε))·∇w_t
  • Instead of summing all past squared gradients, RMSProp keeps an exponentially decayed running average — old gradients "fade out" so the denominator doesn't grow without bound.
  • Result: RMSProp is "less aggressive on the decay" than AdaGrad and can keep making progress even near convergence, where AdaGrad stalls.
  • β is typically 0.9–0.99.

18. Explain the concept of singular value decomposition (SVD) and how it is used in deep learning, with example.

Problem SVD solves: eigenvectors are only defined for square matrices. But most real data matrices A ∈ ℝ^(m×n) are rectangular — SVD generalizes the eigen-decomposition idea to any matrix.

Setup

We look for pairs (vᵢ, uᵢ) with vᵢ ∈ ℝⁿ, uᵢ ∈ ℝᵐ such that Avᵢ = σᵢuᵢ. If {v₁,...,vₖ} form an orthonormal basis for the row space and {u₁,...,uₖ} for the column space, then matrix multiplication Ax again reduces to a simple scalar operation in this new basis (just like eigenvectors did for square matrices).

The decomposition

A = UΣVᵀ

where U (left singular vectors) = eigenvectors of AAᵀ, V (right singular vectors) = eigenvectors of AᵀA, and Σ is diagonal with singular values σᵢ = √λᵢ (square roots of the eigenvalues of AᵀA). This is derived by noting AᵀA = VΣ²Vᵀ and AAᵀ = UΣ²Uᵀ — both are Eigenvalue Decompositions.

Low-rank approximation (key application)

A = Σ(i=1 to k) σᵢ·uᵢ·vᵢᵀ

Theorem: the sum of the top-k terms (ranked by singular value) gives the best possible rank-k approximation of A in Frobenius-norm sense — i.e. min ‖A − B‖²_F over all rank-k matrices B is achieved exactly by this truncated SVD.

Link to PCA / autoencoders

SVD and PCA are closely related: if X is normalized (zero mean), the eigenvectors of XᵀX used in PCA are exactly the right singular vectors V of X. This is also the basis for showing that the encoder of a linear autoencoder equals PCA (see Q21 in Unit III).

Use in deep learning

  • Dimensionality reduction (same mechanism as PCA — low rank approximation compresses data while minimizing reconstruction error).
  • Compressing weight matrices in large models (low-rank factorization, e.g. LoRA-style adaptation).
  • Recommender systems — approximating a large sparse user-item matrix with a low-rank SVD to find latent factors.

20. Discuss how PCA and SVD contribute to feature extraction and computational efficiency in deep learning. Compare their advantages with suitable examples.

  • Feature extraction: both find a new basis that concentrates the "information" (variance) of the data into a small number of dimensions, discarding redundant/noisy ones — the retained dimensions act as extracted features (e.g. eigenfaces from PCA on face images).
  • PCA works specifically on the covariance structure of (typically square, symmetric) XᵀX — requires computing/eigendecomposing an n×n matrix.
  • SVD works directly on the original (possibly non-square, non-symmetric) data matrix A — more general, numerically more stable, and doesn't require explicitly forming XᵀX (which can be numerically unstable — squaring can amplify floating-point error).
  • Computational efficiency: both let you replace a high-dimensional dataset with a low-rank approximation (top-k components) — this shrinks storage (store k basis vectors + k coefficients per sample, instead of n raw features) and speeds downstream training since fewer input dimensions means fewer parameters in the first layer of a network.
  • Relationship: for zero-mean data, PCA's principal components are literally the right singular vectors of SVD applied to the data matrix — SVD is often used as the actual algorithm to compute PCA in practice.
  • Example: compressing m face images of 10,000 pixels each down to k≈100 dimensions via PCA/SVD before feeding into a classifier — retains nearly all discriminative variance while cutting compute drastically.
